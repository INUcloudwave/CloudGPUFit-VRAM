## 2. 100 MB를 넘는 42개 분석

판별 방법: CPU 재생의 최대 할당량(max_allocated)을 GPU `m1_peak_allocated`와 비교한다.
- 같으면 요청량은 맞은 것이다. 이때 오차는 캐시 블록의 재사용·배치에서 생긴다.
- 다르면 요청 목록 자체가 다른 것이다.

| 분류 | 개수 | 할당량 | 오차 범위 | 원인 |
|---|---|---|---|---|
| CNN | 19 | 다름 | +2072 ~ −1798 MiB | 합성곱 경로 차이로 요청 목록이 다르다 |
| 일반 (트랜스포머) | 14 | 같음 | −2240 ~ +170 MiB | 블록 재사용·배치 차이 |
| 재시도 | 9 | 같음 | −326 ~ +790 MiB (상대 0.6 ~ 3.8 %) | 재시도 때 캐시를 해제한 뒤 다시 잡는 주소가 재현되지 않는다 |

- 최대 오차: qwen b128/in1024 2개, −2240 MiB (GPU 18,748 MiB의 −11.9 %).
- CNN은 비율 오차가 일정하다.
  - mobilenet: +30.7 ~ +31.5 % (CPU mkldnn 요청이 더 많아서 과대 예측)
  - resnet-50: −22 ~ −29 % (GPU에 cuDNN 요청이 더 있어서 과소 예측)
  - 오차는 배치 × 해상도²에 비례한다. 작은 입력이 100 MB 안에 드는 것은 절대량이 작아서일 뿐이다.
- qwen 7개는 오차가 정확히 −(배치 × 입력 길이 × 8960 × 2 B)이다.
  - 8960은 MLP intermediate 크기이므로, FP16 MLP 중간 텐서 하나만큼 GPU 캐시가 더 크다.
  - GPU 값이 new_tokens와 무관하다. 따라서 prefill 단계에서 정해진다.
  - 할당 최대치는 GPU와 같다(예: 5929 / 5929 MiB). 요청량 문제가 아니라 블록 재사용 문제다.
  - 무엇이 그 텐서 크기만큼 재사용을 막는지는 GPU 트레이스가 없어 검증하지 못했다(가설 단계).
- 크기 의존성(CNN 제외)

|---|---|---|---|---|---|
| 100 MB 초과 | 0/97 | 0/97 | 4/95 | 6/93 | 13/77 |

| GPU reserved | < 2 GiB | 2 ~ 8 GiB | 8 ~ 16 GiB | ≥ 16 GiB |
|---|---|---|---|---|

## 4. 방법

- 저장된 CPU 요청 스트림(`invocation_fp16_requests.npz`)을 고정된 xMem CachingAllocator(1ee4bd0)로 재생한다.
  - 주소: 인스턴스 단위 패치로 내림차순 정책을 쓴다.
  - LightTrace를 쓴다. stock Trace는 메모리가 폭증한다.
  - 실행 순서는 load → warmup_0..2 → measure_0이다.
- cuBLAS 작업 공간
  - 크기는 8,519,680 B (= 4096 KiB×2 + 16 KiB×8)다. PyTorch 기본 cuBLAS workspace 설정과 같은 값으로 보이며 소스 확인이 필요하다.
  - 위치는 CPU 프로브(`gemm_probe --exact`)로 정한다. 첫 GEMM 출력 요청 바로 다음이다.
  - 522/522 조건에서 프로브 접두부가 저장된 npz 접두부와 같다.
  - 조건별 GPU 결과는 사용하지 않았다.
- 출력 값
  - R_at: 실효 용량에서 measure_0의 peak reserved
  - R_inf: 1 TiB 용량에서 같은 값
  - R_min: OOM이 나지 않는 최소 용량. 2 MiB 단위 이분 탐색으로 구한다.

## 5. 한계

- 규칙을 만든 데이터와 검증한 데이터가 같은 RTX 3090 519개다. 따로 떼어 둔 검증 세트가 없다.
- 다른 GPU나 드라이버에서는 작업 공간 크기, 주소 규칙, 비할당자 크기를 다시 확인해야 한다.
- CNN 합성곱 경로, qwen prefill 재사용, 재시도 후 주소는 모델링하지 않았다. 보정식도 넣지 않았다.
- 원인 검증에 필요한 GPU 트레이스:
  - qwen b32/in1024/new128
  - resnet-50 b128/r512
  - mobilenet b128/r512
  - 재시도 1건
