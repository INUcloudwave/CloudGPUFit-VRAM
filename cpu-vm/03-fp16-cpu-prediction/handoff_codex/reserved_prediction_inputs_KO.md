# Reserved 예측 v3가 사용한 정보와 출처 (2026-11-16, INUOS)

질문: v3 결과를 "시뮬레이션이 예측 시점에 아는 정보만으로 낸 결과"로 볼 수 있는가?
답: **조건별로는 그렇다.** 조건별 GPU 실측값은 예측에 쓰지 않았고, 비교·채점에만 썼다.
다만 아래 B의 규칙들은 INUGPU GPU 트레이스를 분석해서 찾았다. 이 규칙은 시뮬레이터 설계에 해당하고, 조건마다 맞춘 보정값이 아니다.

## A. 조건별 입력 (모두 CPU에서 나온다)

| 정보 | 출처 | GPU 정보 사용 여부 |
|---|---|---|
| 요청 순서·크기 | CPU 실행 트레이스(`invocation_fp16_requests.npz`, FP16 크기로 변환) | 사용 안 함 |
| cuBLAS 작업 공간 삽입 위치 | CPU 프로브(`gemm_probe --exact`): 첫 GEMM 출력 직후. 522/522 조건에서 CPU 스트림 접두부와 일치 | 사용 안 함 |

## B. GPU 종류·소프트웨어별 고정값과 규칙 (모든 조건에 같은 값)

| 항목 | 값 | 출처 | 시뮬레이션이 미리 가질 수 있나 |
|---|---|---|---|
| cuda_total_memory | 25,306,529,792 B | INUGPU measure.json의 environment 값. 장치 속성이라 모든 조건에서 같다 | 가능. GPU 종류별 스펙 값 한 번 |
| 할당자 바깥 사용량 (outside) | 327,155,712 B (312 MiB) | INUGPU L1024 측정(NVML − reserved, 381개 조건 중앙값). **xMem `gpu_overheads.json`의 RTX 3090 outside 값과 같다** (9개 보정 조건으로 따로 구한 값) | 이미 가지고 있음 (xMem outside 표) |
| 작업 공간 크기 | 8,519,680 B | INUGPU GPU 트레이스 12/12에서 관측. PyTorch 기본 cuBLAS 설정(4096 KiB×2 + 16 KiB×8)과 같다 | 가능. PyTorch 버전과 GPU 세대로 계산한다 |
| 작업 공간 시점 규칙 | 첫 GEMM 출력 직후, 해제하지 않음 | INUGPU 트레이스에서 발견 | 규칙으로 코드에 넣는다 |
| 세그먼트 주소 규칙 | 새 세그먼트는 기존 세그먼트보다 낮은 주소 | INUGPU 가이드 §3.3, 트레이스로 확인 | 규칙으로 코드에 넣는다 |

- 조건별로 맞춘 숫자 파라미터는 없다. 오차를 줄이려고 조정한 계수도 없다.

## C. 예측에 쓰지 않은 것 (비교에만 사용)

- GPU 조건별 m1_peak_reserved / m1_peak_allocated
- GPU 재시도 조건 목록과 GPU OOM 목록
  - 그룹을 나누는 데만 썼다.
  - 재시도 여부는 CPU 재생에서 따로 예측해 23/23을 맞혔다.

## D. 주의 (일반화의 한계)

- B의 규칙은 RTX 3090 트레이스에서 찾았고, 같은 RTX 3090 519개 조건으로 평가했다. 따로 떼어 둔 검증 세트가 없다.
- 다른 GPU에서는 B 값을 확인해야 한다.
  - outside: xMem 표에 T4, A10G, L4 값이 있다.
  - cuda_total_memory
  - 작업 공간 크기
- 그다음 그 GPU의 실측과 다시 비교해야 한다.
- 용량 값(B의 첫 두 줄)은 재시도 조건의 reserved 값에만 영향을 준다.
  - 일반 조건과 재시도·OOM 판정은 공칭 24 GiB를 써도 결과가 같다.
