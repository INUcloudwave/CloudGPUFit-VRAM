# T5 환산 규칙 수정 효과 (2026-11-17)

- 대상: L256 표의 t5-small·t5-base 90개 (INUOS에서 성공한 조건 전부)
- 방법
  - 수정 규칙(`--shadow-rule v2`)으로 CPU 실행을 다시 한다 (`runs/rule2_t5`).
  - 예측 방식 v3로 재생한다(실효 용량).
  - 기존 규칙 + v3 결과와 함께 GPU 실측(m1_peak_reserved)에 비교한다.

| 그룹 | 개수 | 기존 규칙: 100 MB 이내 / 정확히 0 / 최대 오차 | 수정 규칙: 100 MB 이내 / 정확히 0 / 최대 오차 |
|---|---|---|---|
| 전체 | 90 | 88 / 55 / 262 MiB | 88 / 57 / 262 MiB |
| 일반 | 88 | 87 / 55 / 242 MiB | 87 / 57 / 242 MiB |
| 재시도 | 2 | 1 / 0 / 262 MiB | 1 / 0 / 262 MiB |

- 예측이 바뀐 조건은 4개뿐이고, 모두 ±2 MiB다.
  - t5-small b8/in256 3개: +2 → 0
  - t5-base b1/128/512: 0 → +2
- 결론
  - 수정 규칙은 요청 단위에서는 맞다(진짜 FP16과의 차이가 절반으로 줄었다).
  - 그러나 t5-small·t5-base의 reserved 예측에는 사실상 영향이 없다. `isinf` 임시 텐서는 곧바로 해제되어 캐시 구성을 바꾸지 않는다.
  - 남은 T5 오차(예: t5-small b128/256/512 −242 MiB)의 원인은 다른 곳에 있다.
- t5-3b는 다시 돌리지 않았다. AWS 진짜 FP16 실행 결과로 대신한다.
