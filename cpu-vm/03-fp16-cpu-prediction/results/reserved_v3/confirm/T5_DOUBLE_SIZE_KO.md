# T5 24 MiB ↔ 48 MiB 원인 (2026-11-16)

- 증상: t5-base b128/128/512의 warmup_0에서 CPU 스트림이 GPU보다 48 MiB 요청이 24개 많고, 24 MiB 요청이 24개 적다.
- 위치 (`t5_align48.py`): 인코더 12층마다 2번, `isinf`의 bool 출력(12 MiB) 바로 앞이다.
  - T5Block FP16 전용 clamp 분기에서 `torch.isinf(hidden_states)`를 호출할 때다.
  - 셀프 어텐션 뒤 1번, FF 뒤 1번이다.
- 연산 출력의 dtype 판정은 맞다 (`tagcheck_shadow.py`: CPU 진짜 FP16 실행과 비교, 5527개 호출 정렬, 큰 텐서 불일치 0).
  - clamp 출력도 'h'로 맞게 매칭된다 (`clampmatch_shadow.py`).
- 원인: `isinf`는 ATen 안에서 `abs(x) == inf`로 계산하므로, 함수 호출에 보이지 않는 내부 임시 텐서 `abs(x)`(입력과 같은 실수 dtype)를 만든다.
  - shadow는 내부 임시 텐서에 "다음에 매칭된 출력의 태그"를 물려준다.
  - 그 출력이 bool이라 태그가 'x'(크기 그대로)가 된다. 그래서 FP32 크기 48 MiB가 남는다.
  - 진짜 FP16 실행(GPU, CPU 모두)에서는 24 MiB다.
  - 같은 위치에 남은 inferred_x 크기 이벤트가 24개로, 층 12 × 2와 같다.
- T5에서만 생기는 이유: 이번 13개 모델 중 FP16에서 큰 텐서에 `isinf`를 부르는 모델은 T5뿐이다.
- 일반 규칙의 한계: 실수 입력을 받아 실수가 아닌 값을 출력하는 연산이 내부에서 실수 임시 텐서를 만들면 같은 문제가 생긴다.
  - 고칠 방향: 내부 임시 텐서의 태그를 출력이 아니라 실수 입력의 태그에서 가져온다 (모델과 무관한 규칙). 아직 적용하지 않았다.
