# 구조 검증: CPU 모델 층 + GPU 라이브러리 층 (2026-11-17)

입력: INUGPU `runs/rtx3090__trace_models`에서 읽기 전용으로 가져온 GPU 트레이스 13개(`/home/inuos/cgf-fp16-inugpu-fetch-20261117`)와 INUOS CPU 요청 목록.
재생 조건: v3 (내림차순 주소, 실효 용량 24,979,374,080 B).

## 1. 할당자 모델 검증 (`gpu_vs_cpu.py`, `gpu_stream_vs_cpu_stream_13traces.jsonl`)

GPU 요청 목록을 그대로 재생했을 때:
- 11/13 조건은 GPU 실측과 정확히 같다.
- 나머지 2개도 차이가 작다: qwen b128/128/512 +8 MiB, t5-3b b8 +2 MiB.

CPU 요청 목록(v3)으로 재생했을 때:
- 트랜스포머 8개(재시도 조건 3개 포함)는 GPU 실측과 정확히 같다.
- qwen b128/128/512 +94 MiB, vit −38 MiB.
- CNN 3개는 크게 다르다.

## 2. CNN 층 분해 (`cpu_layers.py`, `hybrid.py`)

- CPU 요청마다 층을 표시한다.
  - 모델 층: 연산 출력이나 dtype 변환 버퍼와 매칭되는 요청
  - 라이브러리 층: 매칭되지 않는 요청
- GPU 쪽 라이브러리 층은 CPU 모델 층과 짝이 없는 GPU 요청이다.

| 조건 | GPU 실측 | 섞은 목록 재생 (할당 정렬) | 섞은 목록 재생 (이벤트 정렬) | 라이브러리 층을 뺀 두 목록이 같은가 |
|---|---|---|---|---|
| mobilenet b128/r512 | 6580 | **6580** | **6580** | **같다 (4개 실행 모두)** |
| resnet-18 b128/r512 | 2548 | 2548 | 6136 | 다르다 |
| resnet-50 b128/r512 | 6168 | 5142 | 5144 | 다르다 |

- **mobilenet은 분해가 완전히 성립한다.** CPU 모델 층과 GPU 모델 층이 같고, 차이는 라이브러리 버퍼뿐이다.
  - CPU 라이브러리 층은 실행당 17.3 GB(mkldnn)다.
  - GPU 라이브러리 층은 9.6 MB 이하다.
- **ResNet은 CPU 쪽 층 표시가 깨끗하지 않다.**
  - CPU의 batch_norm·relu 출력 일부(256 MiB 크기)가 매칭되지 않아 라이브러리 층으로 잘못 표시된다(`side.py` 출력).
  - 그래서 라이브러리 층을 빼면 실제 모델 텐서도 함께 빠진다.
  - 결과가 짝짓기 방식에 따라 흔들리므로 판정은 보류한다.
- GPU 쪽 cuDNN 작업 공간 패턴 (ResNet): 합성곱 출력을 할당한 직후 작업 공간을 할당하고 바로 해제한다.
  - 크기 예: 7×7 합성곱 1280.02 MiB(출력의 1.25배), 3×3 합성곱 512.07 MiB(2배), 384.14 / 256.28 MiB
  - 합성곱 형태마다 다르다. 규칙은 형태별 표가 필요하다.

## 3. 다음 단계

1. CPU 층 표시 개선: 연산이 반환한 저장소를 기준으로 출력을 판정한다(mkldnn BN·ReLU).
2. 표시를 고친 뒤 ResNet 섞은 목록 재생을 다시 한다.

## 4. CPU 층 구분 수정과 최종 결과 (2026-11-17 저녁)

- 원인: CPU malloc은 방금 해제된 주소를 곧바로 다시 쓴다.
  - 합성곱 안의 임시 버퍼와 진짜 출력이 같은 주소·같은 크기로 연달아 잡힌다.
  - 기존 짝짓기 규칙("가장 먼저 맞는 할당")이 임시 버퍼를 출력으로 골랐다.
  - 증거: "출력"으로 분류된 블록이 다음 연산에 쓰이기 전에 해제되었다(`freeorder.py`).
- 수정 (`cpu_layers2_shadow.py`)
  - 연산이 끝날 때마다 표식 할당(999,983 B)을 넣는다.
  - "연산 종료 시점에 살아 있는, 그 주소·크기의 가장 최근 할당"을 출력으로 판정한다.
  - 표식을 제거한 요청 목록은 저장된 npz와 3/3 같다.
- 결과 (`hybrid4.py`, 순서 보존 짝짓기, 바로 해제되는 블록을 GPU 라이브러리 층으로 우선 분류)

| 조건 | GPU 실측 | CPU 모델 층 + GPU 라이브러리 층 | CPU 모델 층 + cuBLAS 작업 공간만 (GPU 정보 불필요) | 현재 v3 예측 |
|---|---|---|---|---|
| mobilenet b128/r512 | 6580 | **6580** | **6580** | 8652 (+2072) |
| resnet-18 b128/r512 | 2548 | **2548** | 2288 (−260) | 2290 |
| resnet-50 b128/r512 | 6168 | **6168** | 4370 (−1798) | 4370 |

- 세 조건 모두 CPU 모델 층이 GPU 모델 층(GPU 라이브러리 층 제외)과 **해제 순서까지 완전히 같다** (resnet-50 318개, resnet-18 122개 이벤트).
- mobilenet의 과대 예측은 CPU 라이브러리 버퍼(mkldnn)를 빼면 GPU 정보 없이 해결된다.
- resnet의 과소 예측은 전부 GPU cuDNN 작업 공간이다. CPU만으로는 알 수 없으므로 범위(상한)로 다룬다.
