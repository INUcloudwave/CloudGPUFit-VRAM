# AWS GPU 5종(+ gr6 L4 반복)으로 세그먼트 주소 규칙 간접 확인 (2026-11-18, 11-20 gr6 추가)

## 1. 목적과 방법

- 내림차순 세그먼트 주소 규칙은 RTX 3090 GPU 트레이스로만 확인했다(12/12). AWS 결과에는 할당기 트레이스가 없다.
- 간접 확인 방법
  - GPU 요청 목록이 RTX 3090과 같은 조건만 고른다. 기준은 측정 시작 할당량과 최대 할당량이 바이트까지 같은 것이다.
  - 이런 조건에서 reserved 최대값을 정하는 것은 할당자와 세그먼트 주소뿐이다.
  - 이때 AWS GPU의 reserved가 RTX 3090 실측과 같다면, 그 GPU의 할당자·주소 동작은 3090과 같은 결과를 낸다고 본다.
  - 판별용 조건: 기존 xMem 주소(stock)와 내림차순 주소의 예측이 다르고, 3090 실측이 v3 예측(내림차순 + cuBLAS 작업 공간)과 정확히 같았던 조건이다.
- 입력
  - AWS: `~/aws-result` 압축 파일 5개의 `measure.json` (g4dn T4, g5 A10G, g6 L4, g6e L40S, g7 RTX PRO 4500 Blackwell)
  - 예측: `results/reserved_v3/rtx3090_v3/predictions.jsonl` (INUOS CPU, L256)
  - RTX 3090 실측: INUGPU L256 조건별 CSV
- 제외: 어느 한쪽이라도 재시도(num_alloc_retries > 0)가 있었던 조건, 합성곱 모델(cuDNN 작업 공간 때문)
- 실행: `python3 aws_check.py <aws 압축 해제 폴더> <예측 jsonl> <3090 L256 csv> .`

## 2. 결과

| GPU | 같은 요청 목록 조건 | reserved가 3090과 같음 | 차이 2 MiB 이내 | 판별용 조건에서 v3와 같음 |
|---|---|---|---|---|
| A10G (Ampere, torch 2.6) | 292 | 269 | 286 | 48/52 |
| L4 (Ada, torch 2.6) | 275 | 248 | 266 | 48/52 |
| L40S (Ada, torch 2.6) | 275 | 252 | 269 | 48/52 |
| RTX PRO 4500 (Blackwell, torch 2.7.1) | 265 | 238 | 255 | 46/48 |
| T4 (Turing, torch 2.6) | 239 | 151 | 170 | 16/44 |
| L4 gr6.4xlarge (같은 GPU, 다른 인스턴스) | 273 | 246 | 265 | 48/52 |

- **A10G, L4, L40S, Blackwell은 3090과 같은 동작이다.**
  - 판별용 조건에서 v3와 안 맞은 것(4, 4, 4, 2개)은 모두 ±2 MiB 차이다.
    - 작은 블록 풀(2 MiB 세그먼트) 수준의 차이이고, 주소 규칙 차이라면 나와야 할 크기(stock과 내림차순 차이 20~226 MiB)가 아니다.
  - 따라서 이 4종에서는 내림차순 주소 규칙이 3090처럼 성립한다고 판단한다.
- **T4는 판별할 수 없다. 원인은 요청 목록 차이로 보인다.**
  - T5(자체 어텐션 구현, SDPA 미사용): 97개 중 96개가 3090과 2 MiB 이내다. 다른 GPU와 같은 수준이다.
  - SDPA를 쓰는 모델(gpt2, opt, tinyllama, qwen, vit): 142개 중 68개가 2 MiB를 넘게 다르다.
    - T4가 항상 더 작다. 차이는 24, 48, 96 MiB처럼 은닉 상태 크기의 배수다.
    - stock 주소와 내림차순 주소 둘 다 같은 크기만큼 과대예측한다. 즉 주소 규칙으로 설명되는 차이가 아니다.
  - 추정 원인: T4(compute capability 7.5)에서는 PyTorch flash attention 커널을 쓸 수 없어 다른 SDPA 커널을 쓴다. 그래서 측정 구간의 임시 요청 순서가 달라진다. 최대 할당량은 같아도 중간 요청이 달라 쪼개짐이 다르다.
  - 확인하려면 T4의 할당기 트레이스가 필요하다(미확인).

- **gr6.4xlarge(L4) — g6.xlarge와 같은 GPU를 다른 인스턴스에서 측정 (11-20 추가)**
  - 상태: 382 ok / 13 gpu_oom. OOM 조건 13개가 g6와 같다.
  - reserved가 g6와 바이트까지 같은 조건: 376/382. 다른 6개는 gpt2 계열 생성 512 조건 등(−92 ~ +78 MiB)으로, INUGPU 반복 측정(E6)에서 본 실행 간 변동과 같은 종류로 본다.
  - outside 232 MiB(범위 232~236), cuBLAS 8,519,680 B로 g6와 같다.
  - 따라서 같은 GPU 종류면 인스턴스(CPU·RAM 크기)가 달라도 결과가 같다.

## 3. 함께 확인된 것

- **cuBLAS 작업 공간**
  - 측정 시작 할당량에서 로드 직후 할당량을 뺀 값이 5종 모두 디코더 조건 190~192개 전부에서 3090과 같다.
  - 따라서 T4, A10G, L4, L40S(torch 2.6.0)와 Blackwell(torch 2.7.1) 모두 8,519,680 B다. `gpu_rules.VERIFIED`에 반영했다.
- **실효 용량**: `manifest/gpu_profiles.json`에 반영했다. outside = NVML 프로세스 최대 − reserved 최대, measure_0 중앙값.

  | GPU | cuda_total_memory | outside (중앙값, 범위) | 실효 용량 |
  |---|---|---|---|
  | T4 | 15,637,086,208 | 130 MiB (130~132) | 15,500,771,328 |
  | A10G | 23,686,938,624 | 308 MiB (308~312) | 23,363,977,216 |
  | L4 | 23,661,248,512 | 232 MiB (232~236) | 23,417,978,880 |
  | L40S | 47,667,740,672 | 510 MiB (510~514) | 47,132,966,912 |
  | RTX PRO 4500 | 33,689,829,376 | 320 MiB (318~326) | 33,354,285,056 |

- **재시도 없는 조건에서 v3 R_inf가 100 MB 이내인 비율** (비합성곱)
  - A10G 299/309, L4 303/309, L40S 308/319, Blackwell 306/314, T4 283/302
  - 참고: 같은 조건에서 3090 기준 비율은 약 293~303개다.
