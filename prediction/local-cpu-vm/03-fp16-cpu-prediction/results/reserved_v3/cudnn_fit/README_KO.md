# 합성곱 모델 오차 줄이기 1·2단계 + 세대별 cuDNN 작업 공간 표 시험 (2026-11-20)

## 1. 1단계: CPU 라이브러리 버퍼 제거 (GPU 정보 불필요)

- 코드
  - `src/cgf680/layer_shadow.py`
    - 층 분해 실험의 `cpu_layers2_shadow.py`를 일반화했다.
    - 요청마다 소속 연산 이름을 붙이고, 합성곱의 인자(입력·가중치 크기, stride, padding, groups)를 기록한다.
  - `tools/run_layer_labels.py`: 비전 65개 조건 실행. 저장된 요청 목록과 65/65가 같다.
  - `src/cgf680/replay4.py`
    - v3 재생(`replay3`, 무수정)에 넣기 전에 요청 목록을 고친다.
    - `drop="conv"`: 합성곱 호출 안의 CPU 라이브러리 요청만 뺀다.
    - `ws_fn`: 합성곱 출력 직후에 GPU 작업 공간 요청(할당 후 바로 해제)을 넣는다.
- 검증: 층 분해 실험값을 그대로 재현한다(ResNet-50 4370, ResNet-18 2288, MobileNet 6580 MiB).
- 결과 (`fit.py` → `summary.json`, 재시도 없는 합성곱 조건 60개, 100 MB 이내)

| GPU | v3 | 1단계 | 1단계 최대 과대 |
|---|---|---|---|
| RTX 3090 | 41 | **50** | 0 MiB |
| A10G | 41 | **50** | 0 |
| T4 | 42 | **51** | 8 |
| L4 (g6, gr6) | 46 | **55** | 8 |
| L40S | 46 | **55** | 8 |
| RTX PRO 4500 | 37 | **46** | 40 |

- MobileNet 과대예측은 모든 GPU에서 사라졌다.
- 남은 오차는 전부 ResNet의 과소예측이다(cuDNN 작업 공간).
- ViT 5개는 이미 5/5였고 변화가 없다.
- `drop="all"`과 `drop="conv"`의 결과는 같다. 라이브러리 버퍼가 거의 합성곱 안에서만 생기기 때문이다.

## 2. 2단계: GPU별 단일 계수 (기존 실측만 사용) — 실패

- 모든 합성곱에 작업 공간 = r × 출력(또는 입력)을 넣고, GPU마다 r 하나를 맞췄다.
- 결과
  - 모든 GPU에서 최적 r = 0이었다.
  - 모델 하나를 빼고 맞춰 보면 오히려 나빠졌다.
- 원인: cuDNN 작업 공간은 합성곱 종류마다 다르다(아래 표). MobileNet처럼 0인 모델도 있다. 그래서 일률적인 계수는 맞는 조건까지 망친다.

## 3. 세대별 작업 공간 표 시험 (기존 RTX 3090 트레이스만 사용)

- `wsmap.py`
  - RTX 3090 트레이스 3개(ResNet-18·50, MobileNet b128 r512)의 GPU 라이브러리 요청을 CPU 층 정보로 합성곱에 대응시켰다.
  - 결과: `ws_3090_traces.jsonl`
- Ampere(sm86, cuDNN 9.1) 작업 공간 / 출력 배수

| 합성곱 | 배수 |
|---|---|
| 7×7 s2 (첫 층) | 1.25 |
| 3×3 s1 | 2.0 (작은 해상도에서 2.14) |
| 3×3 s2, C→C | 5.0 |
| 3×3 s2, C→2C | 3.0 |
| 1×1 s1 | 0 |
| 1×1 s2 | 0 (64→128, 128→256) 또는 3.0 (256→512 이상) |
| depthwise (MobileNet) | 0 |

- `table_eval.py`: 이 표(b128 r512 두 조건에서 뽑음)를 60개 조건 전체에 적용했다.

| GPU (세대) | 1단계 | Ampere 표 적용 | 비고 |
|---|---|---|---|
| RTX 3090 (Ampere) | 50 | **59/60** | 최대 −96 / +34 MiB |
| A10G (Ampere) | 50 | **59/60** | 3090과 같은 값 |
| T4 (Turing) | 51 | **60/60** | Ampere 표가 그대로 맞음 |
| RTX PRO 4500 (Blackwell, cuDNN 9.7) | 46 | 54/60 | 일부만 맞음 |
| L4 / L40S (Ada) | 55 | 47/60 | 오히려 나빠짐. Ada는 ResNet-50에서 작업 공간을 거의 안 씀 |

- 결론
  - cuDNN 작업 공간은 세대마다 다르다. 같은 세대 안에서는 GPU 모델이 달라도 같다(3090 = A10G, L4 = L40S, 실측 오차도 바이트까지 같음).
  - 한 세대의 표는 배치와 해상도가 달라도 통한다(2개 조건에서 뽑은 표로 58개 다른 조건까지 맞음).
  - 다른 세대에는 그 세대의 표가 필요하다.
- 한계
  - 표에 없는 합성곱 형태는 0으로 처리했다.
  - 표를 뽑은 2개 조건은 평가에도 포함된다. 나머지 58개는 표 밖이다.
  - 모델이 ResNet과 MobileNet뿐이다.

## 5. 3단계 측정 결과로 만든 RTX 3090 표 (2026-11-22)

- 표: `gpu_probe/results/rtx3090/probe_rtx3090.jsonl`
  - 3,253개 합성곱 형태의 1순위 작업 공간이다. 모델이나 트레이스 없이, 형태만 GPU에서 실행해서 얻었다.
- 적용: 각 합성곱 출력 직후에 그 형태의 작업 공간을 넣는다(`replay4`, drop="conv").
- 평가: `probe_table_eval.py` → `probe_table_summary.json`, `probe_table_replays.jsonl`
  - 65개 비전 조건의 모든 합성곱 형태가 표에 있었다(빠진 형태 0).

| GPU (세대) | v3 | 1단계 | 3090 측정 표 | 정확히 일치 | 최대 과대 / 과소 |
|---|---|---|---|---|---|
| RTX 3090 (Ampere) | 41 | 50 | **59/60** | 46 | +2 / −130 MiB |
| A10G (Ampere) | 41 | 50 | **59/60** | 46 | +2 / −130 |
| T4 (Turing) | 42 | 51 | **60/60** | 32 | +8 / −68 |
| RTX PRO 4500 (Blackwell) | 37 | 46 | 54/60 | 23 | +40 / −962 |
| L4·L40S (Ada) | 46 | 55 | 47/60 | 31 | +1794 / −768 |

- 트레이스 배수로 만든 표(§3)와 맞은 개수는 같다. 정확히 일치하는 조건은 33개에서 46개로 늘었다(형태별 실제 값이라서).
- 3090에서 남은 1개는 resnet-18 b16 r512(−130 MiB)다.
  - 작업 공간을 넣어도 1단계와 값이 같다. 따라서 cuDNN 작업 공간이 아닌 다른 원인이다(미확인).
- Ada와 Blackwell은 각 세대에서 같은 측정을 해야 한다(g6, g7에서 `run_probe.sh`). 3090 표를 그대로 쓰면 Ada는 오히려 나빠진다.
